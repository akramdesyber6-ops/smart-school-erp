# Gate Card Attendance

This is the first gate-card attendance slice on `feat/gate-card-attendance`. It is a separate event ledger and does not overwrite the existing class attendance register.

## What is included

- School-scoped gate-reader registry with a one-time issued 256-bit bearer credential.
- SHA-256 credential hashes in the database; the raw reader token is returned only when the reader is created.
- School-scoped student card assignment, with audited card and device revocation.
- A trusted server ingestion endpoint at `POST /api/gate/events`.
- Student resolution from the card UID inside the authenticated reader's school. A reader may not submit a student ID.
- Immutable entry/exit events with reader timestamp, server receive timestamp and a unique per-device event ID.
- Duplicate retry handling and conflict detection.
- School-admin workspace at `/dashboards/school-admin/gate`.

The migration has not been applied to any live Supabase project. Run the migration and pgTAP tests in a disposable project first.

## School administrator setup

1. Open **School Admin → Gate Card Attendance**.
2. Create a reader with a descriptive name. The workspace displays its device code and bearer token once.
3. Copy the token into the reader's secure configuration. Do not put it in source control, client-side JavaScript, public device labels, or support screenshots. If it is lost or exposed, revoke the reader and create a replacement.
4. Read a physical card using the reader/card utility and enter its UID in the student card form. Assign the card to the matching active student.
5. Install/configure reader firmware to send scans to the server endpoint below over HTTPS.

A physical card UID is an identifier, not the device credential. Protect reader tokens as secrets.

## Reader request

Send one request for every scan:

```http
POST /api/gate/events
Authorization: Bearer <64-character-device-token>
Content-Type: application/json
```

```json
{
  "device_id": "a UUID returned when the gate reader was created",
  "event_id": "a unique event ID generated by this reader",
  "card_uid": "A1B2C3D4",
  "event_type": "entry",
  "occurred_at": "2026-10-31T05:30:00+03:00"
}
```

Use `entry` for arrival/on-campus entry and `exit` for departure. `occurred_at` must include a timezone offset. The endpoint accepts queued/offline scans up to 30 days old and rejects timestamps more than five minutes in the future.

The reader must generate a stable unique `event_id` for each physical scan and reuse that same ID when retrying after a timeout. The endpoint returns:

- `201`: a new gate event was accepted.
- `200` with `duplicate: true`: the same event ID and same scan payload had already been accepted.
- `409`: the event ID was previously used for a different scan, the card belongs to an inactive student, or the event conflicts with a prior request.
- `401`: missing/invalid token or revoked/unregistered device.
- `404`: card UID is not active in this device's school.
- `422`: scan timestamp is outside the allowed clock window.

The reader never sends a student UUID. The server first authenticates the device, obtains its school ID from the database, then looks up the active card and its active student inside that school. The database unique constraint is the final duplicate-event guard even when two retries arrive simultaneously.

## Database and security

Migration: `supabase/migrations/20261031000200_gate_card_attendance.sql`

Tables:
- `gate_devices`: device identity, school scope, credential hash, last-seen timestamp and revocation metadata.
- `student_gate_cards`: school-scoped active card-to-student assignments and revocation metadata.
- `gate_events`: append-only scan events with reader ID, card/student IDs and both event/receive timestamps.

RPCs for the signed-in school administrator:
- `public.create_gate_device(target_name)`: creates a device and returns its bearer token once.
- `public.assign_student_gate_card(target_student_id, target_card_uid, target_label)`: maps a physical card to an active same-school student.
- `public.revoke_gate_device(target_device_id)`: permanently disables a reader credential.
- `public.revoke_student_gate_card(target_card_id)`: prevents a card from generating future events while retaining history.

RLS limits device/card management reads to school administrators. Gate-event reads are limited to school administrators and the relevant student/linked parent. The service-role key is used only inside the server endpoint; it must remain server-side. Authenticated clients do not receive permission to insert or edit raw gate events or read device credential hashes.

## Still outstanding

This is not yet a complete physical attendance installation. It does not include firmware for a particular RFID reader (e.g. ESP32/RC522), device health telemetry beyond last-seen, anti-passback rules, automatic present-on-campus reconciliation, correction approvals, notifications, SMS/WhatsApp delivery or gate-event history in parent/student portals. Those should be added as separate changes with hardware-specific tests and notification delivery receipts. The existing daily class attendance register remains independent.
